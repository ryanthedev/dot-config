## Engram

Engram is append-only. Every write is permanent, so it must earn its place.

- **Recall first.** Before non-trivial work, search engram for the project and problem. Hits are leads; confirm them in code or output before you rely on them.
- **Solve methodically.** Reproduce, test one hypothesis at a time, and keep evidence apart from suspicion.
- **Write only verified results.** Never a hypothesis, never mid-investigation.
- **Store lessons, not logs:** gotchas, decisions and why, preferences, outcomes that would change a future approach. One self-contained event: what, why, how verified, date.
- **Skip** what code, git, or docs already say; diffs; task progress; dead ends that taught nothing; secrets.
- **Correct, don't duplicate.** Search before writing. If a stored fact is wrong, ingest a correction that names the stale claim and the new truth.
- **The bar:** would a future session with only the repo get this wrong without the memory? If not, don't write it.
